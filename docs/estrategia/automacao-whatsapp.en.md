# Official WhatsApp Automation

Guide for setting up the WhatsApp channel (Meta's official API) as part of the funnel sequences — confirmation, reminders, recovery, and post-workshop follow-up.

## Technical foundation in the current repository

The CRM already integrates with the **official WhatsApp API (Meta Cloud API)** — it is not an unofficial library nor a workaround built on top of a personal app:

- `packages/zyra-server/src/modules/whatsapp/` — connection via Meta's Embedded Signup OAuth flow and sending of **free-form text** messages through the Graph API.
- `packages/zyra-server/src/modules/whatsapp-webhooks/` — receiving of inbound messages (signed/verified webhook).
- `packages/zyra-server/src/modules/whatsapp-agent/` — automatic responder already connected to an AI model (OpenAI) to qualify/reply to incoming messages (direct foundation for `atendimento-ia.md`).

**Important gap, already flagged in the code itself**: sending today only supports **free-form text messages**, which are only valid within the 24-hour customer service window (the person must have written in within the last 24 hours). **Pre-approved Meta template messages — required to start a conversation outside that window — are not implemented yet.**

This is a real technical blocker for a good part of this funnel: any reminder fired hours/days after sign-up (without the person having replied to anything) requires an approved template, not free-form text. **Before setting up the sequences below in production, this template support needs to be built** — it is the first piece of technical work generated by this document, outside the scope of "just configuration."

## 1. Integration with the official WhatsApp API

- Connect the WhatsApp Business number to the CRM via Embedded Signup (flow already existing in the product) — without relying on a personal number or a third-party bulk-sending tool (which violates Meta's terms and risks the number being banned).
- Register and submit for Meta approval the templates needed for each message outside the 24-hour window (see section 5 — list of templates to create).
- Confirm the number has "green"/high quality rating before scaling volume — new numbers must warm up gradually (a few messages a day, increasing), not start blasting the entire base at once.

## 2. Sign-up confirmation

- Trigger: immediately after the sign-up event creates the record in the CRM (see `crm-e-leads.md`).
- Within the 24-hour window in most cases (immediate message) — can use free-form text today already, without depending on template support.
- Content: confirms the sign-up + delivers the access link + reinforces date/format.

## 3. Automatic reminders

- Trigger: N hours/days before the person's "session" time (see `workshop-automatizado.md`, section 1).
- **Requires an approved template** in most cases, since it normally falls outside the 24-hour window since sign-up.
- Content: reinforcement of value + time urgency, never repeating the confirmation message verbatim.

## 4. Lead recovery

- Trigger: follow-up sequence for people who didn't purchase (see `workshop-automatizado.md`, section 4).
- Mixes free-form text (if the person replied something recently) and template (if there's no recent interaction) — the automation needs to check the last interaction before deciding which message type to send, or simply always use a template for these scheduled sends (simpler and more robust than checking the window dynamically).
- Each message in the sequence is a different template (different objection angles, see `workshop-automatizado.md`) — Meta does not allow reusing the same template for different content; each text variation needs its own approval.

## 5. Follow-ups and post-workshop messages

- Purchase confirmation + access instructions: within the 24-hour window in most cases (follows directly from the purchase interaction).
- Reactivation sequence for those who didn't attend: templates, same logic as sections 3-4.

**Minimum list of templates to submit for Meta approval** (suggested names, adjust to the brand's voice):
1. `confirmacao_inscricao` (fallback in case the immediate send falls outside the 24-hour window due to some delay)
2. `lembrete_sessao`
3. `sessao_liberando`
4. `recuperacao_nao_comprou_1`, `recuperacao_nao_comprou_2`, `recuperacao_nao_comprou_3` (one per objection angle)
5. `reativacao_nao_assistiu`
6. `oferta_encerrando`

Utility vs. marketing templates have different approval rules at Meta (marketing has stricter opt-in restrictions) — confirm the correct category for each one at submission time.

## 6. Consent (opt-in)

- The CRM's `WhatsApp opt-in` field (`crm-e-leads.md`, section 1) must be true before any send outside the 24-hour window — the sign-up page must make it clear that the person will receive WhatsApp messages about the workshop (checkbox or explicit consent text), not just collect the number.
- Any opt-out request ("stop", "unsubscribe", etc.) received via the inbound webhook must automatically mark the record as opted out and end the sequence — the workflow engine (incoming-message trigger + text condition + `update-record`) covers this with no manual work.

---

*Summary of what's left to build before turning this channel on in production: support for sending template messages (today only free-form text exists), and the submission/approval of the templates listed in section 5 with Meta. The rest is configuration of the sequences on top of the already-existing workflow infrastructure (`workshop-automatizado.md`).*
