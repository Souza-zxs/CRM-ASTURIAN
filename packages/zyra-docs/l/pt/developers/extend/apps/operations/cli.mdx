Além de `dev`, `dev:build`, `dev:add` e `dev:typecheck`, a CLI `yarn zyra` fornece comandos para executar funções, visualizar logs e gerenciar instalações de aplicativos.

## Executando funções (`yarn zyra dev:function:exec`)

Execute manualmente uma função de lógica sem acioná-la via HTTP, cron ou evento de banco de dados:

```bash filename="Terminal"
# Execute by function name
yarn zyra dev:function:exec -n create-new-post-card

# Execute by universalIdentifier
yarn zyra dev:function:exec -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf

# Pass a JSON payload
yarn zyra dev:function:exec -n create-new-post-card -p '{"name": "Hello"}'

# Execute the post-install function
yarn zyra dev:function:exec --postInstall
```

## Visualizando logs de funções (`yarn zyra dev:function:logs`)

Transmita os logs de execução das funções de lógica do seu aplicativo:

```bash filename="Terminal"
# Stream all function logs
yarn zyra dev:function:logs

# Filter by function name
yarn zyra dev:function:logs -n create-new-post-card

# Filter by universalIdentifier
yarn zyra dev:function:logs -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf
```

<Note>
Isso é diferente de `yarn zyra docker:logs`, que mostra os logs do contêiner Docker. `yarn zyra dev:function:logs` mostra os logs de execução de funções do seu aplicativo a partir do servidor Zyra.
</Note>

## Gerando o cliente tipado (`yarn zyra dev:generate-client`)

Regenerar o cliente de API tipado (`zyra-client-sdk`) a partir do esquema do remoto ativo, sem compilar nem sincronizar um aplicativo. Use-o para obter um cliente tipado em qualquer projeto — como um serviço de backend em um repositório separado — que se comunica com a sua instância do Zyra:

```bash filename="Terminal"
# In your project (no Zyra app definition required)
yarn add zyra-sdk zyra-client-sdk

# Connect to the Zyra instance to generate the client from
yarn zyra remote:add

# Generate the typed client into node_modules/zyra-client-sdk
yarn zyra dev:generate-client
```

Em seguida, importe o cliente no seu código:

```typescript
import { CoreApiClient } from 'zyra-client-sdk/core';
```

Execute novamente o comando sempre que o seu modelo de dados for alterado para atualizar os tipos gerados.

<Note>
O cliente é gerado dentro de `node_modules`, portanto não é incluído no commit junto com o seu código. Execute `yarn zyra dev:generate-client` após cada instalação (por exemplo, em um script `postinstall` ou no CI).
</Note>

## Desinstalando um aplicativo (`yarn zyra app:uninstall`)

Remova seu aplicativo do espaço de trabalho ativo:

```bash filename="Terminal"
yarn zyra app:uninstall

# Skip the confirmation prompt
yarn zyra app:uninstall --yes
```

## Gerenciando remotos

Um **remoto** é um servidor Zyra ao qual seu aplicativo se conecta. Durante a configuração, o gerador de scaffold cria um para você automaticamente. Você pode adicionar mais remotos ou alternar entre eles a qualquer momento.

```bash filename="Terminal"
# Add a new remote (opens a browser for OAuth login)
yarn zyra remote:add

# Connect to a local Zyra server (auto-detects port 2020 or 3000)
yarn zyra remote:add --local

# Add a remote non-interactively (useful for CI)
yarn zyra remote:add --url https://your-zyra-server.com --api-key $ZYRA_API_KEY --as my-remote

# List all configured remotes
yarn zyra remote:list

# Set the active remote
yarn zyra remote:use <name>
```

Suas credenciais são armazenadas em `~/.zyra/config.json`.
